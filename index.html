    상품 → 한 모델 → 1만 개 중 세부 카테고리. 모델 하나로도 구현할 수 있어 구조가 단순합니다. 후보 검색이나 작은 분류기도 쓸 수 있으므로 반드시 가장 큰 모델이 필요한 것은 아닙니다.

    단계별 · 분야별 모델

    공통 상위 분류 → 전자제품·식품 등의 전문 분류 → 각 분야의 세부 분류. 예를 들어 식품에서는 원재료·상품명, 전자제품에서는 모델명·제품 규격을 중점적으로 살펴보도록 설계할 수 있습니다.

    기대할 수 있는 장점

    각 단계에서 살펴볼 후보가 줄어들고, 분야별 데이터를 활용하거나 한 분야의 모델만 개선할 수 있습니다. 성능·비용·속도 개선은 실제 시험으로 확인해야 합니다.

    함께 고려할 점

    상위 분류가 틀리면 아래에서도 오류가 이어질 수 있습니다. 후보를 여러 개 남겨 재검토하고, 모델별 배포·학습 데이터·버전 관리가 늘어나는 부담을 살펴봐야 합니다.

    화면의 모델은 가상 설계입니다. 현재 움직이는 예시는 전문 모델이 실제 연결된 것이 아닙니다. 대분류별 약 30개의 전문 분류기와 공통 기본 모델을 조합하는 설계를 보여줍니다.

    카테고리가 1만 개면 모델도 1만 개가 필요할까요?

    꼭 그렇지는 않습니다. 모델 수는 카테고리 수가 아니라 선택한 설계와 분류 트리의 구조에 따라 달라집니다.

    공통 기반 + 분야별 분류

    공통 상위 분류기 하나와 전자제품·식품 등 분야별 전문 분류기 약 30개를 둘 수 있습니다. A·B·C는 구분된 역할의 예시입니다.

    기본 모델은 공유 가능

    분야별 분류기가 공통 기본 모델을 공유하고 분야별 판단 부분만 다르게 구성할 수 있습니다. 모델과 운영 자원의 수는 실제 설계에 따라 달라집니다.

    분기마다 모델을 두면?

    부모 분기마다 별도 모델을 두는 설계에서는 분기하는 부모 노드 수만큼 모델이 필요할 수 있습니다. 1만 개 말단 카테고리만으로는 부모 노드 수를 알 수 없습니다.

    오류와 비용 확인

    위 단계에서 잘못 고르면 아래까지 오류가 이어질 수 있습니다. 애매한 상품은 후보를 여럿 남기고, 정확도·처리시간·비용·모델 운영량을 실제 데이터로 비교합니다.

    글로 읽는 진행 순서와 전체 예시 상태
    1. 판매자의 바코드·모델명으로 기존 정보를 찾아 부족한 내용을 채웁니다. 아직 필요한 정보가 있으면 질문하고, 응답이 없으면 기다리지 않고 분류합니다.
    2. 20개씩 25묶음, 총 500개 상품을 장면마다 10개씩 입력합니다. 1차 복제본이 바쁘면 대기열에서 기다리며, 앞선 상품은 아래 단계에서 계속 처리합니다.
    3. 1차에서 정보가 충분하고 최종 후보 점수와 상위 분류가 기준을 충족하면 초록색 경로로 최종 바스켓에 직행합니다.
    4. 그 외 상품은 기존 계층을 따라 내려갑니다. 필요하면 사진을 검사하고 이미지 모델로 확인하며, 해결되지 않으면 사람에게 보냅니다. 경로의 깊이는 분야마다 다릅니다.
    5. 보상 제안이나 직행 기준을 바꾸면 같은 상품의 현재 장면을 다시 계산합니다. ‘처음부터’는 설정을 유지한 채 장면을 0으로 돌립니다.
