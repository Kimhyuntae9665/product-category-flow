        사용하지 않는 모델은 메모리에서 내리고 복제본을 줄입니다. 연결된 유휴 서버·GPU 인스턴스도 축소·중지합니다.

      3. 03 · 재확장

        요청이 늘면 다시 실행

        대기 요청이나 지연이 늘면 모델을 다시 올리고, 정해 둔 최대 실행 수와 예산 범위에서 자원을 늘립니다.

      진행 중인 작업을 마친 뒤 축소합니다. 최소 유지 수와 재조정 대기시간을 두어 재기동 지연과 잦은 증감을 관리합니다. 모델 파일과 학습 자료는 보존합니다.

      직접 운영하는 클라우드·모델 실행 자원을 대상으로 한 계획입니다. 외부 모델 API는 호출량과 동시 요청 수를 조절하며, 모델 복제본 조절과 서버·GPU 인스턴스 정리는 각각 연동합니다.

      설계 참고: Kubernetes 사용량 기반 확장·축소 · KEDA 요청·이벤트 기반 스케일링 · 확인 2026.10.29

      목표는 정확도를 지키면서, 반복 분류와 사람 검수에 드는 비용을 줄이는 것입니다.

      초기 프론티어 호출비용을 검증된 학습 자료와 분야별 모델로 연결하고, 유휴 클라우드·모델 자원은 자동으로 정리하는 방향으로 개선합니다. 실제 총비용을 평가하며 소형 모델의 담당 범위와 실행 자원 규모를 함께 조정하겠습니다.

      전환 시점과 비용을 판단하는 기준

      데이터 개수만으로 전환하지 않습니다. 희귀 카테고리와 사진의 다양성을 확보하고, 같은 상품·유사 사진이 학습 자료와 평가 자료에 함께 들어가지 않도록 나눕니다. 별도 검증 자료로 신뢰도 기준을 정하고, 최종 평가 자료에서 세부 분류 정확도·오분류·자동 처리 비율·사람 검수율을 확인합니다.

      전체 비용으로 비교합니다. 프론티어 호출비뿐 아니라 자료 검수·학습·서버 운영·추가 호출·오분류 수정 비용까지 포함해, 예상 처리량에서 전환할 이점이 있는지 판단합니다. 학습 투자비와 운영비를 실제로 측정하기 전에는 절감률을 확정하지 않습니다.

      이미지로 구분할 수 있는 범위부터 맡깁니다. 설명문에만 있는 규격·성분·호환성은 이미지 모델만으로 배우기 어려우므로 텍스트·프론티어 경로를 유지합니다. 새 분야나 품질 저하가 나타나면 해당 분야를 다시 추가 검토로 보내고 재학습합니다.

      위 내용은 추후 개선 계획입니다. 현재 시뮬레이션에서 실제 데이터 수집·모델 학습·클라우드 자원 정리·성능 및 비용 검증을 수행한 것은 아닙니다.

      설계 참고: PyTorch 전이학습 가이드 · 모델의 예측을 학습 자료로 활용한 연구공개 방법을 바탕으로 구성한 적용안이며, 해당 연구의 성능을 이 서비스의 성과로 사용하지 않습니다.

      설계 참고 자료와 가상 점수 안내

      모든 점수는 고정 합성 수치입니다. 보정 모델을 학습하지 않았으며 자기확신 평균을 확률로 쓰지 않습니다. 실제 적용 전 동일 정답 상품으로 EfficientNet-B0와 ConvNeXt-Tiny를 비교해 하나만 선택하고, 보류한 검증 자료에서 점수 보정·오류율·비용을 확인해야 합니다.

      텍스트 우선 상품 분류 연구 · eBay 최종 후보 추천 · AWS 대기열 자동 확장

      글로 읽는 진행 순서와 전체 예시 상태
      1. 판매자의 바코드·모델명으로 기존 정보를 찾아 부족한 내용을 채웁니다. 아직 필요한 정보가 있으면 질문하고, 응답이 없으면 기다리지 않고 분류합니다.
      2. 20개씩 25묶음, 총 500개 상품을 장면마다 10개씩 입력합니다. 1차 복제본이 바쁘면 대기열에서 기다리며, 앞선 상품은 아래 단계에서 계속 처리합니다.
      3. 1차에서 정보가 충분하고 최종 후보 점수와 상위 분류가 기준을 충족하면 초록색 경로로 최종 바스켓에 직행합니다.
      4. 그 외 상품은 화질 검사 후 전용 이미지 분류기 1개로 확인합니다. 미해결이면 프론티어, 여전히 부족하면 사람검증 점수 +1 뒤 이미지 지원 저비용 모델의 독립 판단·비교를 진행합니다. 미해결 비교는 사람검증 점수 +2, 분기 막힘의 1회 복구는 사람검증 점수 +1이며 매 가산 직후 2점 이상이면 사람에게 보냅니다.
      5. 보상 제안이나 직행 기준을 바꾸면 같은 상품의 현재 장면을 다시 계산합니다. ‘처음부터’는 설정을 유지한 채 장면을 0으로 돌립니다.
