## 어떤 문제를 살펴보나요?

상품 **500만 개**를 약 **1만 개의 세부 카테고리**로 분류해야 한다는 설계 문제를 가정했습니다. 모든 상품에 같은 무거운 처리를 적용하기보다, 상품 정보가 충분한지에 따라 처리 경로를 나누면 어떤 모습일지 시각화했습니다.

실제 화면은 전체 규모를 재현하지 않습니다. **가상 상품 500개와 9개 예시 분야**를 사용하며, 분야마다 2~4단계로 다른 깊이의 분류 경로를 보여줍니다.

## 분류 흐름

```mermaid
flowchart TD
    A[가상 상품 입력] --> B[판매자 정보 보강 예시]
    B --> C[공통 텍스트 분류 작업자]
    C --> D{정보와 최종 후보가 충분한가?}
    D -->|조건 충족| E[최종 카테고리로 직행]
    D -->|추가 판단 필요| F[대분류 → 분야별 세부 분류]
    F --> G[필요한 경우 이미지·다른 모델 검토 예시]
    G --> H{검토 결과}
    H -->|조건 충족| I[최종 카테고리]
    H -->|정보 부족 또는 불일치| J[사람 확인 대기]
```

이 그림은 **제안하는 처리 흐름**이며, 실제 모델과 클라우드 작업자가 연결된 구성도는 아닙니다.

## 화면에서 볼 수 있는 것

### 첫 화면: 전체 분류 흐름과 AI 토론

![텍스트 우선 처리와 선택적 AI 교차 검토를 한눈에 보여주는 첫 화면](assets/overview.jpg)

**“텍스트로 빠르게 분류하고, 텍스트 정보가 부족하면 이미지와 텍스트를 함께 분석합니다.”**라는 핵심 문장과 함께, 상품명·설명으로 먼저 판단하고 필요할 때 사진을 추가로 확인하는 순서를 보여줍니다. 큰 재생 버튼을 누르면 아래의 실제 분류 화면으로 이동하고, 전체 경로가 화면에 들어오도록 자동 축소한 뒤 재생합니다. `크게 보기 / 전체 보기`로 배율을 전환해도 진행 장면은 유지됩니다. 진행 숫자는 500개 상품 시뮬레이션의 같은 재생 상태에 연결됩니다.

![Qwen, NVIDIA Nemotron, Cohere North의 로고와 발언 순서를 보여주는 가상 상품 토론](assets/agent-debate.jpg)

‘이어폰 케이스’를 두고 **후보 제안 → 서로 반박 → 근거 확인**을 직접 넘겨 볼 수 있습니다. 정보가 충분한 경우와 부족한 경우를 바꾸면 예시 결론이 분류 또는 사람 확인 대기로 달라집니다. 이 대화는 **미리 작성한 별도의 설명용 예시이며 실제 AI 응답이 아닙니다.**

PAL에 설정된 **Qwen3.8 27B, Nemotron 3 Ultra, North Mini Code, Gemini 3.8 Flash**의 로고·정확한 모델명·서비스를 표시합니다. `토론 장면 재생`을 누르면 세 참여 모델의 9개 가상 발언을 순서대로 강조합니다. 사진은 텍스트 단서로 전달한 가정이며, 특정 모델의 이미지 처리 능력을 검증한 결과가 아닙니다.

`실제 PAL 설계 검토 기록`에는 이 페이지 설계에 대한 저장된 검토 결과를 별도로 표시합니다. Qwen·Nemotron·North는 독립 검토와 상호 비평을 완료했고, Gemini는 503 오류로 참여하지 못했습니다. 이 기록은 현재 접속 상태가 아니며, 이번 로고 추가 작업에서 새 추론을 호출하지 않았습니다.

판매자 정보와 자동 확장 설정은 상세 시뮬레이션의 접기/펼치기 영역에 있습니다. 모바일에서는 큰 분류도를 좌우로 움직여 읽을 수 있습니다.

### 1. 판매자 정보 보강

![바코드 예시와 일치한 정보를 확인하고 부족한 항목을 자동 채우는 가상 화면](assets/seller-enrichment.jpg)

바코드나 모델명이 가상 상품 정보와 일치하면 부족한 항목을 채우고, 그렇지 않으면 판매자에게 필요한 정보를 묻는 상황을 보여줍니다. 보상 제안을 켜고 끄면 미리 정해진 가상 응답과 분류 경로가 바뀝니다. **실제 조회나 보상 지급은 없습니다.**

### 2. 텍스트 우선 분류와 병렬 작업

![여러 공통 모델 복제본에서 텍스트 경로와 이미지 확인 경로로 나뉘는 실제 화면](assets/classification.jpg)

- 같은 공통 텍스트 모델의 **가상 복제본 10개로 시작**하며, 대기열 상태에 따라 복제본을 늘리거나 줄이는 장면을 볼 수 있습니다.
- 정보가 충분하고 가상 최종 후보 점수와 상위 분류 일치 조건을 충족하면 최종 카테고리로 직행합니다.
- 정보가 부족하거나 판단이 애매한 상품은 계층별 분류와 이미지 확인·추가 검토를 거치는 예시 경로로 이동합니다.
- 여러 상품이 서로 다른 단계에서 동시에 진행하고, 결과는 카테고리별 바스켓에 누적됩니다.

자동 확장의 용량 계산은 **1차 텍스트 단계의 가상 작업자**에 적용됩니다. 하위·이미지 단계의 독립적인 실제 자동 확장은 제안 설계이며, 현재 화면에서 클라우드 자원을 생성하지 않습니다.

### 3. 복구 경로와 누적 검수 점수

![상위 분류로 돌아가는 주황색 경로와 상품별 누적 검수 점수](assets/recovery-review.png)

불확실한 후보는 **상위 단계로 돌아가 대체 후보를 다시 확인**합니다. 주황색 화살표와 `복구 후 통과 / 복구 후 충돌 / 낮은 확신` 버튼으로 세 가지 결과를 비교할 수 있습니다.

| 발생한 일 | 사람 검수 점수 |
| --- | ---: |
| 복구 경로로 재탐색 | +1 |
| 토론 후에도 후보가 충돌 | +1 |
| 추가 검토 후 최종 확신이 매우 낮음 | +2, 위 충돌 점수 대신 |

**2점 이상이면 사람 검수 대기열로 이동**합니다. 같은 상품·원인의 재시도는 중복 가산하지 않습니다. 0~1점도 최종 근거 확인을 통과해야 분류되며, 사진 불량은 점수와 별개로 보류합니다. 점수와 재탐색·토론 결과는 고정된 가상 사례입니다. 실제 AI 추론이나 보정 확률이 아닙니다. 기존 GIF는 기본 흐름을 기록한 것이며, 추가된 복구·점수 동작은 현재 웹 데모에서 확인할 수 있습니다.

### 4. 직접 조작하기

1. **재생 / 한 장면 / 처음부터** 버튼이나 진행 막대를 사용합니다.
2. **가상 보상 제안**과 **자동 확장**을 켜거나 끄고 진행 상태를 비교합니다.
3. 상품을 선택해 정보 보강 내용, 현재 단계와 예시 점수를 확인합니다.
4. 최종 직행·추가 검토 기준을 조절하고 카테고리 바스켓을 살펴봅니다.

## 구현 범위와 한계

| 화면에 구현된 것 | 아직 연결되지 않은 것 |
| --- | --- |
| 500개 가상 상품의 상태 전환과 계층 경로 | 실제 500만 개 상품과 1만 개 카테고리 처리 |
| 텍스트 우선·최종 직행·이미지 검토를 나타내는 규칙 | 실제 텍스트·이미지 모델의 추론 및 모델 간 토론 |
| 1차 대기열·가상 복제본의 확장 및 축소 | GPU 임대, API 호출, 실제 클라우드 자동 확장 |
| 판매자 정보 보강·보상 응답 시나리오 | 실시간 바코드 조회, 판매자 응답 수집, 실제 보상 지급 |
| 미리 작성한 토론의 3단계와 두 가지 정보 조건 | 실제 AI 에이전트 간 대화·추론·판정 |
| 상위 복구·후보 재탐색·중복 없는 검수 점수·검수 대기 목록 | 실제 상품 후보 검색, 사람의 검수 처리·학습 반영 |

화면의 **90·95·70 등의 점수와 기준은 검증되지 않은 예시 값**입니다. 실제 적용 시에는 상품별 정답 데이터로 정확도, 신뢰도 보정, 분류 오류, 처리량과 비용을 별도로 측정해야 합니다. 서로 다른 모델 점수의 단순 평균을 그대로 확률로 해석할 수도 없습니다.

## 실행 방법

서버나 별도 라이브러리 설치 없이 `index.html`을 브라우저에서 열면 됩니다. 웹에서 바로 보려면 [배포된 데모](https://product-category-flow.pages.dev/)를 이용하세요.

Node.js가 설치되어 있다면 아래 명령으로 시나리오 검사를 실행할 수 있습니다.

```bash
node tests/test-text-first.cjs
node tests/test-direct-route.cjs
node tests/test-seller-enrichment.cjs
node tests/test-recovery-score.cjs
```

이 검사는 가상 시나리오의 상태·화면 로직을 확인하며 실제 모델의 정확도나 처리 속도를 측정하지 않습니다.

```text

tests/                       가상 시나리오 검사
```

사용자가 문제와 표현할 흐름을 정하고, Codex를 활용해 웹 화면과 시뮬레이션을 구현·수정했습니다.

첫 화면 아이콘은 [Lucide Static](https://lucide.dev/guide/static) 1.63.0을 사용합니다. ISC 및 일부 Feather 유래 아이콘의 MIT 고지는 HTML에 포함했습니다. 모델 로고는 [Lobe Icons](assets/model-logos/README.md)의 원본 SVG를 사용하고 MIT 라이선스를 보존했습니다. NVIDIA와 Cohere 로고는 각각 Nemotron과 North의 제공사를 식별합니다. 도형과 상품 그림은 자체 SVG이며, 실행 시 외부 라이브러리나 CDN이 필요하지 않습니다. [첫 화면 설계·검수 기록](docs/submission-design.md)에서 적용 범위를 볼 수 있습니다.
